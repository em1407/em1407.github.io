What this project does
🏙️

The challenge

When designing a new neighborhood, urban planners face a key question: which features — parks, offices, sports facilities — actually make residents happier and more socially connected? Traditionally this relied on intuition. We built a data-driven answer.

🤖

The solution

We trained machine learning models on data from existing Dutch neighborhoods to learn which urban features correlate with social wellbeing. The best model — a Random Forest — was then embedded in an interactive app that planners can use in real time.

🗺️

The result

A Shiny App where you select a city (Amsterdam or The Hague), adjust urban feature values, and instantly see how predicted social indicators like loneliness, safety, and quality of life change — neighborhood by neighborhood, on an interactive map.

How it works
01
Data collection & cleaning

We gathered publicly available data on Dutch neighborhoods — everything from the number of green spaces to crime rates and public transport access. The raw dataset had hundreds of columns, many of which were redundant or irrelevant, so we ran a correlation analysis to keep only the most meaningful features.

02
Handling missing values intelligently

Real-world data is never clean. We used a smart imputation strategy: for low-skewness variables we filled missing values with the mean, for medium-skewness we used k-Nearest Neighbors (KNN), and for high-skewness we used the median. This preserved the statistical distribution of each variable.

03
Feature selection with Random Forest + RFE

With 50+ candidate features, we used a Random Forest to rank which urban elements had the most predictive power over social cohesion. We then combined this with Recursive Feature Elimination (RFE) to iteratively remove weak features and keep the most impactful 50 variables.

04
Comparing 5 machine learning models

We evaluated Random Forest, Linear Regression, Support Vector Regression (SVR), Ridge Regression, Polynomial Regression, and Gradient Boosting (GBM) using Leave-One-Out Cross Validation (LOOCV). Each model was scored on MAE, MSE, MAPE, and R². Random Forest came out on top.

05
Shiny App deployment

The winning model was integrated into a Shiny App — an interactive web application built in R. Users can select a city, modify urban feature sliders, and see predicted wellbeing scores update live on a neighborhood map. Designed to be used directly by Amvest's urban planning team.

Technical deep dive

Below is a walkthrough of the most important code sections, with explanations of the decisions behind each step. The full code is available on GitHub.

01 — Correlation-based feature filtering R
# Remove features with low correlation to the target variable threshold <- 0.2 filtered_matrix <- significant_correlations[abs(significant_correlations$Social_cohesion_21) >= threshold, ] # Transpose and filter again to keep only relevant features transposed_matrix <- t(filtered_matrix) cormatrix_refined <- transposed_matrix[abs(transposed_matrix$Social_cohesion_21) >= threshold, ]
We set a threshold of 0.2: any feature with a correlation below this with our target variable (Social Cohesion score) was dropped. This reduced noise and prevented multicollinearity — a common problem when many urban features are naturally correlated with each other.
02 — Adaptive missing value imputation R
for (i in 1:ncol(data)) { skewness_current <- skewness(data[,i], na.rm = TRUE) if (abs(skewness_current) < 0.5) { # Low skewness → use mean data_clean[,i][is.na(data[,i])] <- mean(data[,i], na.rm = TRUE) } else if (abs(skewness_current) < 1) { # Medium skewness → use KNN imputation (k=5) data_clean[,i] <- kNN(data, variable = i, k = 5)[,i] } else { # High skewness → use median (robust to outliers) data_clean[,i][is.na(data[,i])] <- median(data[,i], na.rm = TRUE) } }
Instead of filling all missing values the same way, we adapted the strategy to each variable's distribution. Symmetric variables get the mean. Moderately skewed ones get KNN imputation — which looks at the 5 most similar neighborhoods to estimate the missing value. Heavily skewed variables get the median, which is more robust to extreme outliers.
03 — Random Forest with Leave-One-Out Cross Validation R
for (i in 1:nrow(data_fixed)) { # Train on all rows except i, test on row i train_data <- data_fixed[-i, ] test_data <- data_fixed[i, ] # Fit the Random Forest rfmodel <- randomForest( Social_cohesion_21 ~ ., data = train_data, ntree = 1000, mtry = 10, importance = TRUE ) # Predict and compute metrics pred <- predict(rfmodel, test_data) mserf[i] <- (pred - test_data$Social_cohesion_21)^2 maerf[i] <- MAE(pred, test_data$Social_cohesion_21) maperf[i] <- mean(abs((test_data$Social_cohesion_21 - pred) / test_data$Social_cohesion_21) * 100) }
With a small dataset (neighborhood-level data), standard train/test splits are unreliable. LOOCV solves this: we train on every observation except one, predict that one, then repeat for every row. This gives a reliable performance estimate without wasting data. We used 1000 trees and 10 features per split for a robust forest.
04 — Model comparison results R
Random Forest ✓ Winner
Best overall R² and lowest MAE across LOOCV folds. Handled non-linear relationships between urban features effectively.
GBM
Strong performance but slower to train. Slightly higher MAPE than Random Forest on this dataset size.
SVR
Good with the scaled features but less interpretable for stakeholder communication.
Ridge Regression
Useful baseline. Penalised correlated features well but limited by linearity assumption.
Linear Regression
Weakest performer — urban features have complex non-linear interactions that linear models miss.
Polynomial Regression
Improved on linear but prone to overfitting on the smaller dataset.
Random Forest won because urban data is inherently non-linear — the relationship between, say, green space and happiness isn't a straight line, and it interacts differently depending on other neighborhood characteristics. Random Forests handle these complex interactions naturally.
