What this project does
😤
The challenge

A facial image is just a grid of pixel values — thousands of numbers with no inherent meaning. The challenge is to find a way to compress and represent that information so a machine learning model can tell "disgust" from "neutral".

🔬
The method

We used the Eigenface technique: apply PCA to a dataset of 400 face images to find the directions of maximum variation across faces. These "eigenfaces" capture the most important patterns in facial structure and expression.

🎯
The result

Just 84 principal components — out of 50,176 original pixel dimensions — were enough to explain 90% of the variation across all faces. These compressed representations were used to classify expressions with high accuracy.

How it works
01
Image loading & preprocessing

400 facial images (200 disgust, 200 neutral) were loaded, converted to grayscale, and rescaled to values between 0 and 255. Each 224×224 image was then flattened into a single vector of 50,176 numbers, creating one row per image in a matrix.

02
PCA — finding the "essence" of faces

Principal Component Analysis was applied to the full image matrix. PCA finds the directions (components) that capture the most variation across all 400 faces. The first components capture broad features like face shape and lighting; later ones capture finer details like specific expressions.

03
Selecting 84 eigenfaces

We checked the cumulative variance explained by each component and found that 84 components were sufficient to capture 90% of the total variation. This is a dramatic compression — from 50,176 dimensions down to 84 — while retaining the vast majority of information.

04
Computing eigenface loadings

Each face image was projected onto the 84 eigenfaces to produce a compact "signature" — a vector of 84 numbers that uniquely describes that face in eigenface space. These loadings are what classification models use instead of raw pixels.

05
Classification

The eigenface loadings were used to train classification models to distinguish disgust from neutral expressions. Working in this compressed space makes classifiers faster, less prone to overfitting, and more robust to minor variations in lighting or face position.

Technical deep dive

The core of this project is a clean implementation of the Eigenface pipeline in R. Full code on GitHub.

01 — Image loading & vectorisationR
load_and_process_images <- function(folder_path, image_size = c(224, 224)) { image_files <- list.files(folder_path, pattern = "\\.png$", full.names = TRUE) images <- lapply(image_files, function(file) { img <- load.image(file) gray_values <- grayscale(img) # convert to grayscale gray_values * 255 # rescale to 0–255 }) # Flatten each image into a vector, stack into matrix image_vectors <- lapply(images, function(x) as.vector(x)) matrix(unlist(image_vectors), ncol = image_size[1] * image_size[2], byrow = TRUE) # 400 rows × 50,176 columns }
Each 224×224 image becomes a row of 50,176 numbers. Converting to grayscale first halves the data (no RGB channels), and normalising to 0-255 ensures consistent scale. The result is a 400 × 50,176 matrix — one row per image.
02 — PCA & eigenface selectionR
# Run PCA on the full image matrix PCAProcess <- prcomp(all_images, center = TRUE) # Find how many components explain 90% of variance n_components <- min(which(summary(PCAProcess)$importance[3,] >= .90)) # Result: 84 components # Extract the 84 eigenfaces (rotation matrix) Eigenfaces <- PCAProcess$rotation[, 1:n_components] # Project all images onto eigenface space Loadings <- all_images %*% Eigenfaces # 400 × 84 matrix
center = TRUE subtracts the mean face before PCA — this ensures the components capture variation from the average face, not the average face itself. The matrix multiplication %*% projects each image into the 84-dimensional eigenface space, producing a compact numeric fingerprint for each face.
03 — Visualising eigenfacesR
# Plot the first 10 eigenfaces in a 2×5 grid par(mfrow = c(2, 5)) for (i in 1:10) { # Reshape the eigenface vector back into a 224×224 image eigenface_matrix <- matrix( data = rev(Eigenfaces[, i]), nrow = 224, ncol = 224 ) image(1:224, 1:224, eigenface_matrix, col = gray.colors(256)) }
Reshaping the eigenface vectors back into 224×224 matrices lets us visualise what each principal component "looks like". The first eigenfaces typically resemble ghost-like average faces; later ones capture increasingly specific facial features and expressions. This is one of the most visually striking aspects of the Eigenface method.
